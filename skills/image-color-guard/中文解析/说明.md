# 图片原色守护：完整说明

## 用途

本 Skill 处理连续改图后出现的变深、变灰、饱和度下降、白平衡漂移。它把每轮输出与同一张固定原色图比较，用本地颜色变换纠正能够可靠估计的漂移。它不创造皮肤细节、不消除牛仔裤迷宫纹，不替代人脸一致性修复，也不保证所有生成图都能恢复。

## 为什么不能只在提示词里写“电影级”

图像编辑模型会重新估计光影和材质，“色彩深度、电影级、动态范围”也可能被模型解释为更深的阴影、更低的饱和度。每轮用上一轮输出作为颜色标准，会将已有偏差累积。新流程同时保留“编辑对象”和“固定颜色标准”，生成后再做数值与视觉核验。

## 执行规则

1. 首选素材库中确认过的原色母图。不要从多个旧版本中猜，不默认最新最深的一版更准确。没有既有母图时，固定本轮任务开始前的原图。用户能明确批准新的基准，但工具不会自行覆盖清单。
2. `init` 将原图绝对路径与 SHA-256 写入本地清单；原图字节变动会停止执行。跨设备移动文件需核对 hash 后更新路径，不能换图冒用同一基准。
3. 每轮生成前声明参考职责，生成后用 `check`；所有候选与原图保留。不要覆盖原始文件，不以用户未确认的校正候选更新人物 golden。
4. 脚本先按 EXIF 方向及嵌入 ICC 转为 sRGB；无 ICC 的 RGB 约定为 sRGB。不支持无配置的 CMYK；不确定的配置报错，不能声称绝对色准。输入输出应在色彩管理正常的同一查看器中比较。
5. 底层先对齐结构、排除显著变化区域，在未改动区域拟合单调色阶曲线与按交叉验证选择的颜色映射，不重画人物。审计将过亮白底排除，重点观察未改动主体。参考“灰”主要用 CIELAB 彩度比判断，不能把“更鲜艳”一概当更准确。
6. 审计固定使用同一批样本比较校正前后，默认容差：明度偏移绝对值≤1.5 L*、彩度比0.95–1.05、对比度比0.92–1.08、平均ΔE00≤2.5，且色差不能明显恶化。这是工程复核阈值，不是经过普适验证的人类视觉保证。
7. 色彩样本不足时相应彩度/对比度值为 null，而不是“零偏差”；必须按场景目视检查。没有可靠结构或主体样本就标记 review。数值是可对照区域上的测量，不能代表全图每个新物体。
8. 换装/换背景可加入白色排除蒙版。校正映射仍会作用于整张图，须检查有意的新颜色是否保持。自动估计无法覆盖所有主体局部偏移；保留对比图。
9. 用户明确要求整体重新打光、黑白、复古调色或夜景，用 intentional-grade 跳过自动回色并记录原因，不能反向抹掉其请求。旧锚点不自动变更。只说“电影级精修”不等于要求变暗变灰。
10. 全新构图、全新场景和大幅改姿势常常无法与原图可靠对齐；不做全局直方图匹配，不以强制提亮替代判断。色调通过后仍需验收身份、皮肤、布料与锐化伪影。工具缺失或校正失败时明确说出未完成部分。

## 生成提示词固定追加段

> 保持已确认原色基准的曝光、白平衡、中间调明度、主体色彩浓度与自然对比关系。仅实现本轮要求的修改。摄影精修通过光线平衡与真实细节体现；保持原本的明亮程度、肤色血色、衣物颜色和背景白度。输出后以固定原图检查色调。

### 用户指定的电影级词条（原文保留）

> 将这张照片转化为精修的电影级画质，看起来像是用专业全画幅相机和高端镜头自然拍摄的。增强真实锐度、精细细节、动态范围、光线平衡、色彩深度和色调。

追加解释：该词条强调细节与成像质量，原色守护段同时约束曝光和色彩；不默认为新的整体调色要求。不要堆叠“浓郁暗调、压低黑位、低饱和电影滤镜”等未经要求的词。

## 使用方法

```bash
# 将 <skill> 换成安装目录，使用具备 requirements.txt 依赖的 Python。
python <skill>/scripts/guard.py init --source /data/model/original.png --manifest /data/model/color-anchor.json
python <skill>/scripts/guard.py check --manifest /data/model/color-anchor.json --image /data/model/edit-01.png --out-dir /data/model/round-01
# 下一轮仍用同一个 manifest，而不是把 edit-01 注册成基准。
python <skill>/scripts/guard.py check --manifest /data/model/color-anchor.json --image /data/model/edit-02.png --out-dir /data/model/round-02
# 换衣时排除被有意修改的颜色区域。
python <skill>/scripts/guard.py check --manifest /data/model/color-anchor.json --image /data/model/red-shirt.png --ignore-mask /data/model/shirt-white-mask.png --out-dir /data/model/round-03
# 明确要求整图夜景：仅记录有意调色跳过，不输出虚假的“校色成功”。
python <skill>/scripts/guard.py check --manifest /data/model/color-anchor.json --image /data/model/night.png --mode intentional-grade --out-dir /data/model/night-report
```

`check` 生成 `<输入名>_color-guard.png`、同名 JSON 与 `_compare.png`。同名输出存在时停止，改用新版本目录。JSON 记录原图、输入、输出 SHA-256、拟合信息、主体审计、状态与对比图路径。临时 sRGB 文件在运行后移除；不得将临时路径当作可复用资源。

## 示例与验收

- “只换白T恤为蓝T恤”：原图做颜色基准，最新图做换衣对象，排除新T恤拟合；检查皮肤、裤子、背景未被压暗。新T恤的颜色由本轮要求决定。
- “修肤质”：皮肤细节可变，但明度和血色维持基准；不能把磨皮变灰当精修完成。色调关卡不保证肤质已经好转。
- “把背景变成暖色黄昏”：本轮有意变光，记录跳过整体回色，按用户意图验收；需要以后沿用此暖光时由用户确认新基准。
- `review` 例：“校正后彩度比0.91，主体仍偏灰；保留候选，未通过验收。” 不说“已经彻底解决”。

## 安装与默认调用的边界

本包可复制到个人 skills 目录。agents/openai.yaml 开启默认可选；用户要求的“每次改图调用”还应写入其本机 AGENTS.md。它是代理执行约定，不是能拦截所有外部软件输出的后台插件。新聊天应读取到该规则和 Skill；新设备需同步安装。没有访问原图或执行脚本的环境，必须说明检查未运行。

测试：`python <skill>/scripts/test_guard.py`；测试覆盖变暗去色、局部有意改色、同图不变、固定原图校验和无法对照的画面。测试素材由脚本合成，无私人照片。
